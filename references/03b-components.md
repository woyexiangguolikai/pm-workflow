# 03b 素材库（Component / Motion / Pattern Library）

**产出**：`library/` 目录 —— **不是本次交付的产物，是一个跨项目、持续增长的资产**。

> **这一层是唯一会随使用时间增值的部分。** 前面每一层（需求 / PRD / 设计规范 / 原型）做完就归档了，
> 只有素材库越用越值钱。所以它的设计目标不是「这次产出完整」，而是**「三年后还敢用」**。

---

## 1. 它解决什么问题

设计师/产品平时会**零散地收藏**：看到一个好的骨架屏动效、一个巧妙的空状态、
一段值得抄的交互模式 —— 存在浏览器书签、微信群、备忘录里，**下次做项目时想不起来，也找不回来**。

素材库把这件事变成工作流的一环：

```
平时：看到合适的 → 当场入库（3 步，见 §3）
用时：跑 03 设计规范 / 04 原型 之前 → 先查库挑，挑不到再自己设计
```

**两条纪律，决定了库会不会死**：
1. **不是「有库就必须用」**。库是备选不是规定。优先级：需求约束 > 项目设计规范 > 库。
2. **挑中就要回填 `usedBy`**。不回填，半年后你无法回答「这条到底有没有人用过」，
   也就无法清理 —— **只进不出的库会退化成坟场**。

## 2. 目录结构

```
library/
├── README.md              # 给人看的用法（怎么加、怎么挑、许可纪律）
├── index.json             # 机器索引 —— 由脚本生成，禁止手写
├── components/            # 组件：按钮、输入、卡片、列表项、弹层…
│   └── c-0001-loading-button.md
├── motions/               # 动效：加载、转场、反馈、微交互…
│   └── m-0001-skeleton-shimmer.md
├── patterns/              # 交互模式：提交、撤销、空状态、分步、错误恢复…
│   └── p-0001-optimistic-submit.md
└── local/                 # 私有区：不入 git，豁免许可校验
```

**三种类型的边界**（决定一条素材该放哪）：

| 类型 | 是「什么」 | 例 |
|---|---|---|
| `component` | **一个可复用的界面单元** | 加载按钮、只读金额字段、底部抽屉 |
| `motion` | **一段随时间变化的表现** | 骨架屏微光、成功打钩、列表项入场 |
| `pattern` | **一套跨组件的交互做法** | 乐观提交、分步表单、空状态引导 |

⚠️ 分不清时按「**用户感知到的是单元、是动画、还是一套做法**」来判。
放错目录不会报错，但会让检索时漏掉它。

## 3. 怎么加一条（三步）

1. **挑目录**：`components/` / `motions/` / `patterns/`
2. **建文件**：`<前缀>-<4位序号>-<英文短名>.md`（如 `c-0003-bottom-sheet.md`）
   —— 序号**在同一类型内**递增，`c-0001` 与 `m-0001` 可并存
3. **贴 front-matter + 正文**，然后跑一次：

```powershell
python "$env:USERPROFILE\.workbuddy\skills\pm-workflow\feedback\checks\check-library.py" `
  "$env:USERPROFILE\.workbuddy\skills\pm-workflow\library" --index
```

`--index` 顺手重算 `index.json`。**这个文件不要手写**（同全流程铁律：改数据源 → 重新生成视图）。

### front-matter 字段

```yaml
id: c-0003              # 短、稳定。引用它时用这个 —— 改名会让所有引用失效
type: component         # component / motion / pattern
name: 底部抽屉
tags: [overlay, mobile, 选择器]
summary: 移动端从底部升起的半模态面板，用于选择器与轻量表单
license: mit            # ★ 硬门槛，见 §4
sourceUrl: https://example.com/xxx     # 自有原创写 _original_
capturedAt: 2026-10-11  # 判断「是否已过时」的时间锚点
support: Chrome 90+ / Safari 15+       # 必须带版本数字
status: active          # active / stale / deprecated
usedBy: []              # 被哪些项目/页面用了 —— 长期为空 = 坟场
```

### 正文的六节（顺序固定）

`一句话` → `什么时候用` → **`什么时候别用`** → `实现要点` → `无障碍` → `依赖` → `反面参照`

🔴 **`什么时候别用` 是全文最重要的一节。** 截图人人会存，**判断力才是资产**。
一条没写「别用场景」的素材，半年后一定会被误用 —— 而那正是你当初觉得它好的原因。

## 4. 🔴 许可纪律

**这是整个库里唯一会让你惹上麻烦的地方，而且它不会报错，只会在交付前夜暴露。**

| 允许 | 拦下 |
|---|---|
| `original`（自写）· `public-domain` · `CC0-1.0` | **`GPL` / `AGPL` / `LGPL`** —— 传染性，衍生作品也要开源 |
| `MIT` · `Apache-2.0` · `BSD-2/3-Clause` · `ISC` · `0BSD` | **`CC-BY-NC*`** —— 禁止商用 |
| `CC-BY-4.0` / `CC-BY-3.0`（**须保留署名**） | **`CC-BY-ND`** —— 禁止演绎（改了就是违约） |
| | **未标注** —— 与「不允许使用」等价处理 |

**看到素材时的动作顺序**：
1. 先找 **LICENSE / 仓库根目录 / 页面底部**，确认许可。
2. 找不到 → **入库时写 `license: unknown`**，检查器会拦下（这是故意的，不是缺陷）。
3. `CC-BY` 类必须**在正文里写清署名要求**，否则交付时会漏。

> **这条判据绝不能推给人** —— 人是记不住 200 条素材的许可的，机器记得住。

## 5. 工作流怎么吃这个库

跑 **03 设计规范 / 04 原型** 之前，先查库：

```
1. 读 index.json（只读 summary，别读全文），按 type / tags 挑候选
2. 读候选的「什么时候别用」一节        ← 这一步最容易被跳过，也最容易出事
3. 挑中的写进 usedBy，并记下用了它的页面/端
4. 没有合适的 → 才自己设计；设计完若能复用，回填入库
```

**挑中的素材如何落进设计规范**：素材进库时是**通用描述**，被某个项目采用时才需要落到具体 token ——
即把条目 `依赖` 里建议的变量（如 `--brand-500`）映射到该项目的实际 token。
**映射关系写在项目里，不写在库里** —— 库必须保持项目无关，否则第二个项目就不能复用了。

## 6. 退役（让库能减负）

过时了不可怕，**可怕的是它还在库里、还长得像能用的样子**。

```yaml
status: deprecated
replacedBy: c-0007      # 换成谁（必须指向存在的 id）
# 或
status: stale
keepReason: 团队内部约定仍在使用，兼容老项目
```

**A7 会强制这条**：`deprecated`/`stale` 必须给 `replacedBy` 或 `keepReason`，否则判失败。
**没有退役机制的库会从资产退化成负债**（同 rubric 的判据失效纪律）。

## 7. 校验

```bash
python <skill>/feedback/checks/check-library.py <library_dir> [--index] [--json out]
python <skill>/feedback/checks/check-library.py --selftest
```

**A 类 8 条**：字段齐全 · id 规范 · 来源可溯 · **许可白名单** · 无重复 · support 可判失效 ·
status 与退役后事 · index 不漂移。

**变异测试必须先过**（好样本全绿 **且** 坏样本全红），否则该检查等于没有检查。

输出里要重点看两个数字：
- **`已被引用: N / M`** —— 长期为 0 说明库在坟场化；
- **`许可分布`** —— 出现 `unknown` 说明有素材没查清来源。

## 8. 常见坑位

| 坑 | 表现 | 对策 |
|---|---|---|
| **文件名 `_` 开头** | 曾用「`_` 开头则跳过」的约定 → `_draft-c-0003.md` **完全消失在统计外**（不报错、不计入、无法察觉） | 只跳 `README`；无 front-matter 的 `.md` 必须被判失败。**被跳过的文件必须被看见。** |
| **`support` 写「现代浏览器」** | 看着填了、实际不可判 —— 三年后没人知道还能不能用 | 必须带版本数字 |
| **`tags` 写了等于没写** | 全填 `[ui]` `[通用]`，检索时等于没有标签 | 3–6 个，包含**场景词**（`选择器`、`移动端`）而非只有**形态词**（`圆角`） |
| **`usedBy` 永远是空** | 库涨到 300 条后你会开始不看它 —— 因为它没有可信度 | 挑中即回填 |
| **把含客户信息的素材放进公开目录** | 它会随 git 分发给所有人，**你替下游用户承担了风险** | 只能进 `local/` |
