# 04 原型 · 质量标尺（rubric）

> **怎么用**：本文件在 04 阶段**常驻注入**。A 类由 `checks/check-prototype.py` 自动判；
> B 类由自评**逐条给证据**，人评**只处理打问号的项**。
>
> **本阶段判据的来源**：全部来自**实际踩过的工程坑**（见 `references/gotchas.md` 与
> `anti-patterns.md`）。坑一旦变成检查项，就不会再踩 —— 这是把经验转成资产的标准动作。

## A 类 · 可脚本化（必须自动判，不许推给人）

| 编号 | 判据 | 判定线 | 怎么判 |
|---|---|---|---|
| A1 | **JSX 嵌套合法**：`<a>` 不嵌套 `<a>`；`<span>` 内不含块级元素 | 0 处 | **必须排除自闭合标签**，否则兄弟节点会被误判为子节点 |
| A2 | **离线包本地引用可达**：`href` / `src` 中的本地相对路径目标必须存在 | 0 处死链 | **只查显式链接属性**，不扫任意字符串 |
| A3 | **页面数与声明一致**，且各处声明自洽 | 全一致 | 从 `<端>_SCREENS` 数组**现算**，不写死 |
| A4 | **五端齐备**：5 个端注册表，每端至少 1 页 | 5 端且无空端 | 扫 `window.<端>_SCREENS = [` |
| A5 | **硬约束落点可指认**：每条不可改约束能指到具体页面 | 0 处「真缺陷」 | 落点写成页面编号 → 机械可查（原 B2 升级）。**失败集只有三类**：`没写落点` / `落点上游也不存在` / `全部落点都在本原型外` |
| A6 | **离线包真可用**：`file://` 渲染零报错、跨页锚点真实生效、无孤页 | 全部满足 | **必须真渲染**，见下（原 B4 升级） |

### A6 为什么不能用静态分析替代（原 B4 的注解）

原型是 Babel 在浏览器里现编译的 React 应用，**页面结构不存在于 HTML 源码里**。
对源码 grep `id="U-02"` 一个都找不到，而运行时 23 个页面一个不少 ——
静态查会把「全通」报成「全断」。

而**就算真有 id 也不能只看 id**：页面切换走 `history.replaceState(null,"","#"+code)`，
DOM 里根本没有对应 id。唯一可靠的做法是真导航过去、看渲染结果是否**确实变了**。

A6 拆成四条，每条都有它单独要挡的东西：

| 子判据 | 挡什么 |
|---|---|
| A6-1 渲染零报错 | 双击打不开、控制台报错 |
| A6-2 跨页锚点真实生效 | 锚点写错；**以及「写了路由代码但没生效」** |
| A6-3 从入口出发每页可达 | 有页面进得去出不来 / 根本没有入口指向它 |
| A6-4 判别力自证 | 渲染本身不可复现 —— 那样 A6-2 的「变了」只是噪声 |

**A6-4 是这条判据的自我证明**：两次无 hash 加载的签名必须一模一样。
基线不稳定时 A6-2 的结论**一并作废**，而不是「通过」。

> 🔴 **这条判据踩过一个花了半天的假绿**：首版从 `A.html` 导航到 `A.html#X`，
> 结果 23 个锚点**全部**报「未变化」。根因是**同文档导航** ——
> 只改 hash 不触发 load、不重跑脚本，而应用只在 mount 时读 `location.hash`，
> 于是导航无效，探针等 load 等到超时后采样到**旧 DOM**。
> → 修法：每次导航都带一个唯一的 `?wb_probe=N`，把「同文档」变成「跨文档」。
>
> 教训与 AP-06 同源：**「没有变化」既可能是被测对象的问题，也可能是探针的问题。**
> 所以判据里必须自带一个能区分这两种情况的控制项。

### 两条判据的注解（都来自实测假阳性）

**A1 必须排除自闭合标签。**
首版正则 `<span\b[^>]*>` 会把 `<span className="node" />` 当成开标签，
于是紧随其后的**兄弟** `<div>` 被判定为子节点 —— 5 处命中全是假阳性。
写法：`<span\b(?:(?!/>)[^>])*>`。

**A2 只查 `href` / `src` 属性，不扫任意 `.html` 字符串。**
首版按「任意 .html 字符串」扫描，命中的两处全是假阳性：
- `error-decoder.html` —— React 生产包自带的错误解码器引用
- `index.html` —— 交付导航页正文里的一句「index.html 本页 · 交付导航台」

> **判据一旦把文档正文和第三方产物当成缺陷，人就会开始忽略它。**

## 元规则（管 rubric 自己）

1. **能一眼判真假的才是判据，判不了的只是口号。**
2. **写完任何 A 类判据必须做变异测试**（`--selftest`）：好样本全绿 **且** 坏样本全红。
3. **假阳性必须改判据，不能靠人工忽略。**
4. **过时的判据要能失效**，见 `review-log.jsonl`。

### 正则解析结构化文本的两类高频陷阱

写 A 类判据几乎都要用正则，以下两类最常造成假阳性：

| 陷阱 | 表现 | 对策 |
|---|---|---|
| **贪婪回溯** | `23 页` 被 `(\d+)端?\s*(\d+)` 切成 `2` + `3` | 量化范围要与语义对齐；歧义处加非捕获组约束 |
| **空元素 / 自闭合** | `<span ... />` 被当作开标签，吞掉后面的兄弟节点 | 用 `(?:(?!/>)[^>])*` 排除 |

### A5 的失败集为什么要收窄（2026-10-11）

初版把「落点页面**不在本原型内**」也判失败。实测触发在硬约束 #8 / #10 上，落点是 `M-15`、`M-11` ——
但这两页**不是冗余项**：它们是交互说明书页面地图里真实存在的**简设页**，
而且 `M-15 扫码核销页` 是交互说明书明确列出的**三个完成事件触发页之一**（`R-05 送达确认 / M-15 扫码核销 / M-04 已出餐`），
**而约束 #8 管的就是「完成事件必须二次确认」**。

按初版判失败，整改动作会变成「**把 M-15 从落点里删掉**」——做 M-15 的人从此看不到这条约束。
**方向对（确实有假红）不等于动作对（删错了东西）**，这是 AP-09 的同一个教训。

所以：`const HARD` 是**项目级**硬约束登记表，不是「本原型 N 页」的目录。改后规则 ——

| 情形 | 判定 | 为什么 |
|---|---|---|
| 落点在本原型内 | ✅ | 可直接指认 |
| 原型内 ≥1 个 + 上游简设页若干 | ✅（简设页部分**告知**） | 约束仍可在本原型内指认；简设页也该遵守它 |
| **全部**落点都在原型外 | ❌ `no_landing` | 在这个交付物里**无从指认** —— 这必须失败 |
| 落点上游页面地图里也没有 | ❌ `not_upstream` | 真悬空 |
| 一个落点都没写 | ❌ `no_ref` | 沉默不等于确认（AP-04） |

**判别力必须逐例验证**（不能只看「跑绿了」）：原型内→pass；原型内+简设页→pass；只有简设页→fail；上游无→fail；两个简设页→fail。

> 这条修正的一般形式：**判据的失败集要收「修法明确且改对了」的那些情形。**
> 如果一条失败信息的整改动作是「删掉一个真实存在的东西」，那这条判据的边界画错了。
