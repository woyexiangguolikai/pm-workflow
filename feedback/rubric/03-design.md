# 03 设计 · 质量标尺（rubric）

> **怎么用**：本文件在 03 阶段**常驻注入**。A 类由 `checks/check-design-tokens.py` 自动判；
> B 类由自评**逐条给证据**，人评**只处理打问号的项**。
>
> **为什么需要它**：`tokens.css` 的文件头写着「改主色只需改 `--brand-500` 一处」。
> 这是**可被证伪的承诺** —— 只要任何地方出现该色值的另一种写法（hex / rgb / rgba），
> 承诺就是假的，而使用者不会知道。**把承诺变成检查，是 rubric 存在的意义。**

---

## A 类 · 可脚本化（必须自动判，不许推给人）

| 编号 | 判据 | 判定线 | 怎么判 |
|---|---|---|---|
| A1 | **主色单一事实源**：品牌主色值在样式与渲染代码中 0 处复制 | 0 处 | 色值归一化后全仓比对（hex / rgb / rgba 三种写法都算） |
| A2 | **无复制 token 色值**：除 tokens.css 外无硬编码 token 值 | 0 处 | 豁免纯黑白、`rgba()` 叠加、HTML 文档提及 |
| A3 | **深色主题完整性**：`--bg-*` / `--text-*` / `--border*` 全部被深色主题覆盖 | 全覆盖 | 排除 `--text-on-*` |
| A4 | **正文对比度**：`--text-1` / `--text-2` 在 `--bg-page` / `--bg-surface` 上 | ≥ 4.5:1 | WCAG 相对亮度公式，沿 `var()` 链解析 |
| A5 | **无游离色值**：代码中的不透明色值全部来自 token | 0 处 | 与 token 色值集合取差集 |
| A6 | **公共组件声明与实现可机械对齐**（+ 四态齐备） | 差集为空 **且** 四态 = 4 行 | 交互说明书 §6 的「组件名」声明 vs 设计系统源码的 `function Xxx(` |

### 三条豁免的判定依据（都来自实测假阳性）

**A1 只判 `.css` / `.jsx` / `.js`，不判 HTML。**
交付导航页里写「当前用的是 #E4572E」是**文档**，不是样式 —— 换色时它本来就该改。
把它判红会让判据失去可信度。

**A2 豁免纯黑 / 纯白与 `rgba()`。**
`#fff` 是通用底色，不是色板成员；`rgba(...)` 表达的是**透明度叠加**，语义与色值不同。
首轮实测中这两类占了 29 处命中里的 25 处，全属假阳性。

**A3 排除 `--text-on-*`。**
`--text-on-brand` 的语义是「品牌底之上的文字色」，它跟随**品牌色**而非主题。
深色主题不覆盖它是正确的。

**A5 是最有产出的一条**：它抓的不是「写错」，而是「设计系统之外还长了颜色」。

## A6 · 公共组件声明与实现可机械对齐

**为什么它是 A 类**：交互说明书 §6 开篇自己写着「前端对应组件命名建议写在每项末尾的括号中，
**便于设计稿与代码对齐**」。这句话把一个承诺摆在了明面上 ——
**只要名字对不上，承诺就是假的，而使用者不会知道**（设计师拿着 `MoneyText` 去代码里搜，搜不到）。

这与 `tokens.css` 文件头那句「换主色只改一处」是同一类承诺，处理方式也应相同：**把承诺变成检查**。

### 两侧的书写形态（都是实测存在的，不是猜的）

**声明侧** = 交互说明书第六章的「组件名」声明。有三种形态：

| # | 形态 | 例子 |
|---|---|---|
| ① | 表头行含「组件名」列 | `\| 状态 \| 使用场景 \| 设计要求 \| 组件名 \|` |
| ② | 行首标签行（2 列表格的末行） | `\| 组件名 \| \`MoneyText\`（含 \`precision\`…） \|` |
| ③ | 加粗引导行 | `**组件名**：\`ConfirmDialog\`（…）` |

不一律要求某一种 —— 三种都是「把组件名列出来」的稳定写法。
但**只认这三种**，不做全文 CamelCase 扫描：那会把正文里顺手提到的名字也算成声明。
**判据不能把「提及」读成「声明」。**

**实现侧** = 设计系统源码（默认 `src/ui.jsx`）里的 `function Xxx(` + `window.Xxx =`。

### 别名登记：唯一写法

```
`声明名`（实现 `实现名`）
```

**为什么必须有别名**：`EmptyState` / `ErrorState` 在实现里**都是 `State`**（用 `art` 区分），
把声明侧改成 `State` 会**丢掉「四态」这个信息** —— 改名不是正确答案。
把两个名字的关系写下来，才是。

### 三个闸门（缺任一条都会退化成橡皮图章）

| 闸门 | 判什么 | 不加会怎样 |
|---|---|---|
| C1 控制项 | 声明侧或实现侧解析出 **0 个** → 直接 fail | 任一侧样本为空，差集必然为空 —— 那不是「对齐」，是没看 |
| C2 对齐 | 声明侧 ∖（实现侧 ∪ 别名目标）= ∅ | — |
| C3 四态齐备 | 标题含「四态」的小节必须解析出 **4** 个含组件名的状态行 | 只判命名会漏掉「状态确实没设计」这一半 |

C3 **按标题内容（含「四态」）定位，不按节号** —— 节号一改（6.1 → 6.2）判据就失效。
这与 04 A7 用「逐级向上找线框图」而不是写死路径是同一条纪律：**别把位置写死进判据。**

### 实现侧多出来的名字**不计缺陷**

设计系统允许有内部组件（`Swatch`、`Sec`、`DemoCtl`…），它们不需要出现在交互说明书里。
判据只判「声明了却没有」这个方向。**反方向的差集只作告知** ——
两个方向都判会制造大量假阳性，判据一旦假阳性就会被整体忽略。

### 判定线为什么不是「一一对应」

§6 的原话是「建议」二字修饰**位置**（写在括号中），不是修饰**对齐**。
对齐的目的是被显式声明的。所以差集必须为空；对不上就必须**显式登记别名**，
不允许「反正差不多」。

## B 类 · 需人判（判据必须可核对）

| 编号 | 判据 | 怎么算不过 |
|---|---|---|
| B1 | **待定义项闭环**：交接文档 §六 列出的待定义项逐项有定义 | 任一项无定义且无「有意不定义」说明即不过 |
| B2 | **不可改约束可指认**：每条硬约束都能指认到具体落点 | 有约束找不到落点即不过 |
| B3 | **主题是活代码**：深色主题可实际切换生效，而非仅有声明块 | 只有 `[data-theme="dark"]` 声明、无切换入口即不过 |
| B4 | ⬆️ **组件状态齐备**（命名与四态部分已升级为 A6） | **A6 自动判**：声明名对不上实现 / 四态不足 4 行即不过。剩下「每个组件的禁用·加载·错误态**长得对不对**」仍在这里人判 |

## 元规则（管 rubric 自己）

1. **能一眼判真假的才是判据，判不了的只是口号。**
2. **写完任何 A 类判据必须做变异测试**（`--selftest`）：好样本全绿 **且** 坏样本全红。
3. **假阳性必须改判据，不能靠人工忽略。**
4. **过时的判据要能失效**，见 `review-log.jsonl`。

> ⚠️ **A 类判据还有一个反向陷阱**：如果解析逻辑失效（选择器匹配不到、路径写错），
> 全部判据会**静默假绿** —— 每项都返回 pass，看起来比真实结果更"健康"。
> 本轮实测就踩到了（见 `anti-patterns.md` AP-06）。
> **变异测试是唯一能发现这件事的手段。**

### A6 首跑实测（2026-10-11）

声明侧 14 个 · 实现侧 28 个 · 四态行 4（C3 通过）· **C2 报出 11 处未对齐**：

```
Badge(6.6) · Banner(6.6) · ConfirmDialog(6.4) · EmptyState(6.1) · ErrorState(6.1) ·
FormField(6.5) · MoneyText(6.2) · NoticeBar(6.6) · ReasonInput(6.5) · Skeleton(6.1) · VoucherUploader(6.5)
```

**方向判定靠的是引用面，不是措辞**：

| 名字 | 被几份文档引用 | 有实现？ |
|---|---|---|
| 声明名（`MoneyText`/`EmptyState`/`ConfirmDialog`/`NoticeBar`…） | **2–3 份** | 多数无 |
| 实现名（`Chip`/`SkeletonCard`/`ConfirmModal`/`Notice`） | **0 份** | 有 |

→ **声明侧是契约，实现侧才是偏的**。这一条不是「判据太严」，是真缺口。
整改方向应是把实现名对齐到契约名（或对确实共用一个实现的登记别名）；
4 个在源码里完全无对应的（`Banner` / `FormField` / `ReasonInput` / `VoucherUploader`）
需要决定是补实现还是显式声明「本期不实现」。

⚠️ **判据报出后不要在文档侧「登记别名」制造绿色** ——
那会把「实现没跟上契约」变成「契约迁就了实现」，问题的性质被换掉了。
