# 01 需求 · 质量标尺（rubric）

> **怎么用**：本文件在 01 阶段**常驻注入**。A 类由 `checks/check-requirements.py` 自动判；
> B 类由自评**逐条给证据**，人评**只处理打问号的项**。
>
> **本阶段判据的重心**：需求清单是**编号体系的源头**。它一旦有断链或编号漂移，
> 下游 PRD / 原型 / 卡片全部跟着错位。所以这里的核心判据是**跨文档闭环**，不是格式美观。

---

## A 类 · 可脚本化（必须自动判，不许推给人）

| 编号 | 判据 | 判定线 | 怎么判 |
|---|---|---|---|
| A1 | **功能点编号连续唯一**（每端内独立连续，如 `F-U-01…`） | 无缺号无重复 | 按端分组现算 |
| A2 | **五端合计与概览表声明一致** | 现算一致 | 概览表数字 vs 实际条目数，两侧都从数据源现算 |
| A3 | **优先级取值合法**（Must / Should / Could 三值闭集） | 100% | 扫优先级列 |
| A4 | **每条有「对应 FR」或显式「—」** | 100% | 空值判失败（空 ≠ 无对应） |
| A5 | **「对应 FR」列的引用在 PRD 中存在且形态合法**（跨文档闭环） | 0 处悬空 / 0 处形态非法 | 词表只有四种：`FR-xx` / `NFR-xx` / `§x.y` / `—`。前三种各自校验存在性（FR 编号存在 / NFR 编号存在 / **章节标题**存在）；解析掉合法引用后**余下必须只剩分隔符** |
| A6 | **例外清单与明细行一致**（文档声明的「产品补充」名单必须等于明细行里「对应 FR」为 `—` 的行集合） | 0 处矛盾 | 声明处 = **一个标题块**，块内**行首**的功能点编号才算声明；与明细行 `—` 集合**双向相等**（多一个不行、少一个也不行）；只允许一处声明 |

### A6 是第二轮补上的 —— 它抓的是 A1–A5 结构上抓不到的一类

**发现的经过**：06 卡片阶段比对「卡片 vs 功能列表」时，卡片的 `F-U-47` 写了
「—（产品补充功能点，待评审）」，而上游明细行写的是 `FR-25`。顺着查下去才发现，
功能列表**自己**在第七章声明了两份「产品补充」名单，而这两份名单：

- **彼此不一致**：第 444 行列 4 项（F-U-47 / F-O-59 / F-R-23 / F-C-10），第 447 行列 6 项（F-U-09 / F-U-47 / F-O-31 / F-O-59 / F-C-10 / F-C-12），交集只有 3 项。
- **与明细行大面积矛盾**：两份名单共涉及 7 个编号，其中 **5 个的明细行里填着真实存在的 FR 编号**（F-U-09→FR-11、F-O-31→FR-10、F-U-47→FR-25、F-O-59→FR-15、F-C-12→FR-51）。

A1–A5 **全都抓不到**：编号是连续的、数量是对的、FR 也确实存在于 PRD。
**唯一能抓到它的是「拿声明去核明细」** —— 所以才有 A6。

> 这条印证了 rubric 的元规则 1：**能一眼判真假的才是判据。**
> 「这份清单准不准」在 A6 之前不是判据，只是印象；写成 A6 之后它变成一个可复现的数字。

#### A6 实现上的两次踩坑 —— 都是「提及」被读成「声明」

A6 的初版用「**全文档任意提到『产品补充』且带编号的行**」当声明，结果同一个坑踩了两次：

| 次序 | 触发形态 | 后果 |
|---|---|---|
| 第 1 次 | 文档里写「上一版曾列入本清单、现已移出……**不属产品补充**」 | **否定句被读成肯定声明** —— 假阳性无法靠修改文档消除，最终只能被人忽略，然后判据失效 |
| 第 2 次 | 「产品补充清单」表格**某一行**的说明列写了「**同 F-M-07**」 | 该行主张的是 `F-M-44`，但 `F-M-07` 也被提取成被声明项（它其实有 `FR-22`） |

结论：**「限定在标题块内」是必要不充分条件，本质约束是「行首」** —— 只有行首编号才算「主张」，
行文中提到的编号只是「引用」。改完以后声明处与引用处在**形态上**就能分开，不再依赖关键词。

> 判据的元规则补一条：**假阳性如果能靠「让人别那么写」消除，那就不是假阳性，是判据错了。**
> 这里两次都不是文档写错，是判据把「提及」当成了「断言」。

### A5 是本阶段最重要的一条

断链有两种，**只有第二种会被 A5 抓到**：
- FR 编号写错（如把 `FR-14` 写成 `FR-41`）→ 会指向**另一条真实存在**的需求，肉眼极难发现
- FR 编号指向**不存在**的条目 → A5 直接报出来

两端都要能算：编号集合必须**从两边现算**，任一侧写死都会让判据失效。

#### A5 的合法词表为什么是四种，而不是「只有 FR-xx」

需求清单的「对应 FR」列在真实项目里会指向三类东西，硬压成一种必然造假：

| 形态 | 指向 | 校验方式 |
|---|---|---|
| `FR-xx` | 第七章功能需求 | 编号存在（可并写 `FR-13/14`） |
| `NFR-xx` | 第八章非功能需求 | 编号存在 |
| `§x.y` | **既非 FR 也非 NFR** 的正文依据（方案选型 / 上线流程 / 数据回收等） | PRD **标题**里存在该章节号 |
| `—` | 无依据（产品补充） | 由 A6 反向核 |

两个实现上的坑（都踩过）：

1. **`FR-` 正则必须加负向后顾 `(?<![A-Z])`** —— 否则 `NFR-03` 里的 `FR-03` 会被当成功能需求引用。
2. **必须做「残留检查」** —— 只判断「能不能解析出东西」会把 `FR-01 见 8.2` 这种脏单元格放行：它看着有编号，实际是两种语义糊在一起。解析掉全部合法引用后，余下必须只剩分隔符。

> ⚠️ **不要把「非 FR 的正文依据」硬塞进 `NFR-xx`**。「灰度与回滚」「方案选型」不是非功能需求；
> 把它们标成 `NFR-xx` 是**分类错误**，下游会按非功能需求去对待一份上线流程。
> **结论不准确，整改就会做错**（AP-09）。`§x.y` 这种形式本来就已在 PRD 正文里使用，引入它没有成本。

### 为什么 A4 要把「空」判失败

「没有对应 FR」和「忘了填」在数据上长得一样。**必须显式写「—」才算表态** ——
这与 `anti-patterns.md` AP-04 是同一个道理：沉默不等于确认。

## B 类 · 需人判（判据必须可核对）

| 编号 | 判据 | 怎么算不过 |
|---|---|---|
| B1 | **澄清无遗漏**：约定的澄清域逐项有结论 | 任一域标「没问到」即不过 |
| B2 | **假设已闭合**：无未确认假设混在需求里 | 出现未标注的推测性条款即不过 |
| B3 | **工作量口径明确**：产能基数与推算过程写明 | 只给结论不给口径即不过 |
| B4 | **功能点可独立理解**：单看一条不依赖前文 | 需要回翻上文才能读懂即不过 |

## 元规则（管 rubric 自己）

1. **能一眼判真假的才是判据，判不了的只是口号。**
2. **写完任何 A 类判据必须做变异测试**（`--selftest`）：好样本全绿 **且** 坏样本全红。
3. **假阳性必须改判据，不能靠人工忽略。**
4. **过时的判据要能失效**，见 `review-log.jsonl`。

### 写本阶段判据时的两个已知坑

| 坑 | 表现 | 对策 |
|---|---|---|
| **概览表与明细表互相印证** | 概览表的合计数本身也是手写的，可能和明细不一致 | 两侧都现算，不一致时报「内部矛盾」而非「数量错」 |
| **编号分端独立** | `F-U-01…` 与 `F-O-01…` 各自连续，不能跨端连号 | 先按前缀分组，再逐组查连续性 |
