# 03b 素材库 · 质量标尺（rubric）

> **怎么用**：本文件在 03b 阶段**常驻注入**。A 类由 `checks/check-library.py` 自动判；
> B 类由自评**逐条给证据**，人评**只处理打问号的项**。
>
> **本阶段判据的重心**：其他阶段判「这一次做得好不好」，本阶段要判
> **「这条素材以后还敢不敢用」**。
>
> 03b 不是一个交付阶段，是一份**会一直长下去的资产**。所以它的判据不围绕「产出完整」，
> 而围绕三件事：**敢不敢用（许可）· 找不找得到（可检索）· 有没有人用（有效性）**。

---

## A 类 · 可脚本化（必须自动判，不许推给人）

| 编号 | 判据 | 判定线 | 怎么判 |
|---|---|---|---|
| A1 | **必填字段齐全**（id / type / name / tags / summary / license / sourceUrl / capturedAt / support / status / usedBy） | 100% | 逐条查键；无 front-matter 的文件同样判失败 |
| A2 | **id 唯一、前缀匹配 type、文件名以 id 开头** | 100% | `c-`/`m-`/`p-` + 4 位；`[cmp]-\d{4}` |
| A3 | **来源可溯**（`sourceUrl` 非空 + `capturedAt` 是合法 `YYYY-MM-DD`） | 100% | 逐条校验 |
| A4 | **许可在白名单内** | 100% | ★ **硬门槛**，见下 |
| A5 | **无重复条目**（`type` + 排序后 `tags` + `summary` 的指纹唯一） | 0 处重复 | 指纹去重 |
| A6 | **`support` 含版本数字**（可判失效） | 100% | 正则查数字 |
| A7 | **`status` 合法；退役素材交代后事** | 100% | `deprecated`/`stale` 必须给 `replacedBy`（且指向存在的 id）或 `keepReason` |
| A8 | **`index.json` 与目录一致** | 0 处漂移 | 由 `--index` 生成后比对 |

### 🔴 A4 是本阶段唯一「拦下来」而不是「报出来」的判据

| 允许 | 拦下（附理由） |
|---|---|
| `original` · `public-domain` · `CC0-1.0` | `GPL`/`AGPL`/`LGPL` —— **传染性**，衍生作品也须开源 |
| `MIT` · `Apache-2.0` · `BSD-2/3-Clause` · `ISC` · `0BSD` | `CC-BY-NC*` —— **禁止商用** |
| `CC-BY-4.0` / `CC-BY-3.0`（需保留署名） | `CC-BY-ND` —— **禁止演绎** |
| | `proprietary` —— 专有，未获授权不得使用 |
| | **未标注** —— 与「不允许使用」等价处理 |

**为什么这条绝不能推给人**：素材库会长到 200 条以上，**没人记得住其中 30 条分别是什么许可**。
而「忘了记许可」和「许可就是不允许商用」在数据上长得一模一样。
这是整个反馈层里**法务后果最直接**的一条判据，也是唯一一条「宁可误拦，不可放过」的判据。

### A6 抠的是「看起来填了、实际不可判」

`support: 现代浏览器` —— 看着填了，实际等于没填：三年后没人能判断它还能不能跑。
这与 AP-06（静默假绿）是同一类：**字段有值 ≠ 字段可用**。
必须带版本数字（`Chrome 90+`），否则到期无法判失效。

### A7 让库能「退役」

一条素材过时了不可怕，**可怕的是它还在库里、还长得像能用的样子**。
所以退役必须交代后事：`replacedBy: c-0007`（换成谁）或 `keepReason: 团队内部约定仍在使用`。
**没有退役机制的库会从资产退化成负债**（同 README 的判据失效纪律）。

## B 类 · 需人判（判据必须可核对）

| 编号 | 判据 | 怎么算不过 |
|---|---|---|
| B1 | **「什么时候别用」有真判断力** | 该节写成套话（「视情况而定」）或干脆没写即不过 |
| B2 | **素材真的适配目标端**，不是看着好看就收 | 无法说出它对应哪个端 / 哪类页面的即不过 |
| B3 | **动效不打断任务**（motion 类）：可关闭、不阻塞、时长短于 1.8s | 有强制播放、无法跳过、超长动画即不过 |
| B4 | **来源可复核**：按 `sourceUrl` 能再找到同一素材 | 打开是首页 / 404 / 内容不符即不过 |

### B1 为什么排第一

库的真正价值不在「这条素材长什么样」，而在**「什么时候不该用它」**。
截图人人会存，判断力才是资产。**一条没写「别用场景」的素材，半年后一定会被误用。**

## 元规则（管 rubric 自己）

1. **能一眼判真假的才是判据，判不了的只是口号。**
2. **写完任何 A 类判据必须做变异测试**（`--selftest`）：好样本全绿 **且** 坏样本全红。
3. **假阳性必须改判据，不能靠人工忽略。**
4. **过时的判据要能失效**，见 `review-log.jsonl`。

### 写本阶段判据时的两个已知坑

| 坑 | 表现 | 对策 |
|---|---|---|
| **静默跳过 = 静默假绿** | 曾用「文件名 `_` 开头则跳过」的约定 —— `_draft-c-0003.md` 会**完全消失在统计外**：不报错、不计入、无法察觉 | **只跳 README**；无 front-matter 的 `.md` 必须被 A1 报出来。**被跳过的文件必须被看见。** |
| **同一缺陷重复报警** | 无 front-matter 的文件会让 A1–A7 全部红一次，噪声淹没真问题 | A1 报完后，后续判据只看 `hasFrontMatter` 的条目 —— **同一缺陷只报一次** |

### 私有区的处理（有意为之，非漏洞）

`library/local/` 是私有区，**豁免 A4 许可校验**（这正是它的用途）。
但豁免**必须可见**：检查器会输出 `localExempt` 条数，而不是静默放过。

> ⚠️ 反向风险：若有人把素材全部堆进 `local/`，许可闸门就被绕过了。
> 所以 `local/` **不入 git**，它只能保护你，保护不了下游 —— 用法上必须区分清楚。
