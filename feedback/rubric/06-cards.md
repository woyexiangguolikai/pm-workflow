# 06 需求卡片画布 · 质量标尺（rubric）

> **怎么用**：本文件在 06 阶段**常驻注入**。A 类由 `checks/check-cards.py` 自动判；
> B 类由自评**逐条给证据**，人评**只处理打问号的项**。
>
> **本阶段判据的重心**：卡片是交付链的**末层**，它把前面每一层的内容**再抄一遍**（优先级、FR、页面编号）。
> 末层抄错，前面全对也没用。所以这里的核心判据是**向上一致性**，不是卡片写得好不好看。

---

## A 类 · 可脚本化（必须自动判，不许推给人）

| 编号 | 判据 | 判定线 | 怎么判 |
|---|---|---|---|
| A1 | **卡编号与功能列表一一对应**（不增、不删、不改名） | 差集为空 | 两侧编号集合取差集（前者需 `--features`） |
| A2 | **每卡六段齐全**（涉及端 + 优先级·对应FR / 需求要点 / 关联与数据来源 / 变更影响面 / 页面流转） | 100% | 逐卡解析段名，缺段即报 |
| A3 | **关联四类逐类表态且非空**（无则写「无」） | 100% | 功能依赖 / 数据来源 / 状态联动 / 流程上下游 |
| A4 | **涉及端取值在闭集内**（`UC`/`MC`/`RC`/`OA`/`CS`/`SVC`） | 100% | 扫标题行的端代号 |
| A5 | **优先级与对应 FR 与功能列表一致** | 0 处漂移 | 逐卡与上游同行比对（不是各自合法） |
| A6 | **页面流转引用的页面编号在上游存在** | 0 处悬空 | 与交互说明书的页面编号集合取差集 |
| A7 | **变更影响面写明「具体表现」**（覆盖率 + 空话模板 + 复述检测） | 覆盖率 ≥ 95% **且** 空话 0 处 **且** 复述 0 处 | 逐卡解析「变更影响面」段；三条机制各报各的 |

### A1 / A5 / A6 的共同逻辑：末层不产生新事实

卡片层是**只读层** —— 它引用上游，不定义上游。因此它的三条跨文档判据都是**取差集 / 逐条比对**，
而不是「检查卡片自己合不合理」。

### A5 的边界（重要）

A5 **只判「与上游一致」，不判「引用本身是否合法」** —— 合法性归 01 A5。

**实测例（2026-10-11 已闭环）**：原先功能列表与卡片里 `F-M-41` 的对应 FR 都写着 `8.3`（不是 FR 编号）。

| 阶段 | 看到的 | 判定 |
|---|---|---|
| 改前：两侧都写 `8.3` | 一致，但不合法 | **01 A5 fail**（形态非法）/ **06 A5 pass**（一致） |
| 若只改一侧为 `NFR-03` | 漂移 | 06 A5 fail |
| 改后：两侧都写 `NFR-03` | 一致且合法 | 两侧全绿 |

#### 这两条判据的分工，带出一个操作纪律

**改上游的引用形态，必须同时重跑下游。** 本轮 01 A5 改完后，06 A5 **立刻报出卡片层同样 9 处未同步** ——
如果只修上游不重跑下游，交付链就会在最后一层带着 9 处漂移交货，而**没有任何判据会替它叫**。
所以：**01 的 A5 与 06 的 A5 是同一根链子的两端，改一端就必须跑另一端**（这正是「判据链会互相发现盲区」的又一次实例）。

> **同一缺陷只在一个阶段报。** 若 02/03/06 都去重新校验 FR 引用的合法性，
> 同一个问题会被报 6 次，人会开始整体忽略这个判据 —— 判据被无视一次就永久失效了。

## B 类 · 需人判（判据必须可核对）

| 编号 | 判据 | 怎么算不过 |
|---|---|---|
| B1 | **数据来源栏体现「本端不得自造」强约束** —— ⛔ **已探测，确认留在 B**（理由见下） | 资金类卡片未写明由服务端下发即不过 |
| B2 | ⬆️ **具体表现说得够不够具体**（主力已升级为 A7） | 落点缺失 / 纯套话 / 整段复制前半句 → **A7 自动判**；剩下「换了词的套话、泛泛而谈」仍在这里人判 |
| B3 | **跨端卡片逐端分列且注明各端做什么** | 只写端代号不写括号说明即不过 |
| B4 | **四类关联非「为了填而填」** | 填写内容与本卡无实质关系即不过 |

### A7 与 B2 的分工：升级不等于判完

B2 原来写作「写的是具体表现，不是『同步更新』—— 出现空话即不过」。**它可判**，
因为两侧都有稳定形态：一边是「具体表现：」落点标记，一边是套话模板。
按纪律，可判的部分必须自动化，不能挂在 B 类"等有空再说"。

但 A7 只能判到**三种形态缺陷**：

| 机制 | 抓什么 | **抓不到什么** |
|---|---|---|
| 覆盖率（≥95%） | 整批卡片不再写落点标记 | 写了但内容空 |
| 空话模板 | 「具体表现：同步更新。」这类纯模板 | 换了词的套话 |
| 复述检测（重合 <85%） | 把前半句整段复制过来 | 换几个词重说一遍（约 0.5–0.8 重合） |

「这段具体表现**说得够不够具体**」要懂这张卡的业务语境，正则判不了 ——
**那部分仍留在 B2**。

> **把 B 类升级成 A 类，是把可判的部分自动化，不是宣布剩下的部分已经判过了。**
> 若升级后直接把 B 行删掉，等于把抓不到的那部分**静默豁免**。

#### A7 的控制项（为什么它不会退化成橡皮图章）

| 控制项 | 不加会怎样 |
|---|---|
| **样本为 0 → 直接判失败** | 段名一改 / 格式一变，「覆盖率」在空集上恒等于 1，判据静默全绿 |
| 空话模板比对**剥掉模板后剩余的字节数**，不是比对「有没有出现模板词」 | 「须全端同步更新金额明细」会被误判成空话 → 假阳性 → 判据被整体忽略 |
| 复述检测有**独立的坏样本** | 三条机制只测一条，另外两条是不是死代码没人知道 |

实测判别力（`--selftest`，四个 A7 专项反例各盯一条机制）：

| 样本 | 期望 | 实得 |
|---|---|---|
| 控制项·样本为 0 | `['A2','A7']` | ✅ 一致 |
| 缺「具体表现」落点 | `['A7']` | ✅ 一致 |
| 只写套话模板 | `['A7']` | ✅ 一致 |
| 把前半句复制成具体表现 | `['A7']` | ✅ 一致 |

真实项目边际（207 张卡）：落点覆盖率 **207/207 = 100%**；空话 **0 处**；
复述最高重合度 **0.23**（阈值 0.85）—— 两侧都有 2 倍以上余量，不存在贴着阈值跑的情况。

## B1 为什么判不了（已探测，别再试）

B1 原文：「数据来源栏体现『本端不得自造』强约束 —— 资金类卡片未写明由服务端下发即不过」。
它读起来可判，但**三组独立探测都指向同一结论：不可机械判**。

| # | 试过的形态 | 实测结果 | 为什么不成立 |
|---|---|---|---|
| 1 | 数据来源含资金词（金额/分账/退款…）→ 必须出现「不得自造」类表述 | 39 张卡命中，**22 张报缺** | **22/39 是假阳性** —— 「退款金额由 `SVC` 依订单实付计算」本来就是在说服务端下发，只是措辞不同。合法表述太多，任何词表都会漏 |
| 2 | 覆盖率制：数据来源必须对本端可写性表态 | **205/208 通过** | 不是判据，是橡皮图章 —— 一个永远为真的判据等于没有 |
| 3 | 窄版：**需求要点**谈钱的卡，数据来源必须提服务端 | 25 张命中，**9 张报缺** | **9/9 全是假阳性**，根因见下 |

### 探测 3 暴露的根因（这条才是真正值钱的部分）

第 3 版抓到的 9 张卡，全是**录入 / 配置类**：商户定价（`F-M-26`/`F-M-27`）、
运营配分账规则（`F-O-31`）、线下退款登记（`F-M-20`）… 它们本来就**应当**由本端产生。

> **「谁产生这个值」与「这个值能不能被本端算出来」是两件事。**
> 录入类卡片本端产生 = 正确；计算类（金额明细、分账结果）本端产生 = 违规。
> **而在文本上，两者都写成「由 `MC` 产生」—— 判据分不开。**

要分开，只能靠**语义判断**：得知道这个值是不是「算出来的」。
那是人判，不是正则。所以：

> **B1 留在 B 类。** 这不是「等有空再说」，是实测确认判不了。
> 若日后要在 A 类里碰它，唯一可行的方向是从**上游字段规格的 `服务端 · R` 标记**出发
> （那里有稳定标记），而不是从卡片的措辞出发。

## 元规则（管 rubric 自己）

1. **能一眼判真假的才是判据，判不了的只是口号。**
2. **写完任何 A 类判据必须做变异测试**（`--selftest`）：好样本全绿 **且** 坏样本全红。
3. **假阳性必须改判据，不能靠人工忽略。**
4. **过时的判据要能失效**，见 `review-log.jsonl`。
5. **B 类只有两种归宿**：被判据消费掉，或**带着「试过、不行、为什么」的结论留下**。
   含糊地留在 B 类，下次会有人再试一遍。

### 写本阶段判据时的两个已知坑

| 坑 | 表现 | 对策 |
|---|---|---|
| **编号互相包含** | `F-U-01` 里含 `U-01`；用 `\bU-\d{2}\b` 提取页面编号会把 207 个卡号全当成页面号（实测多报 100+ 个） | 提取前先屏蔽 `F-[A-Z]-\d+`；或用**负向后顾** `(?<![A-Za-z0-9-])` |
| **段名出现在字段定义章节** | 第二章「二、卡片字段定义」也写着「关联与数据来源」等段名，直接全文计数会多出 3–5 个 | **必须先切卡片块，再在块内解析**，不能全文 grep 计数 |
