# 02 PRD · 质量标尺（rubric）

> **怎么用**：本文件在 02 阶段**常驻注入**。A 类由 `checks/check-prd-md.py` 自动判；
> B 类由自评**逐条给证据**，人评**只处理打问号的项**。
>
> **为什么要有它**：pm-workflow 原有的 check 全是「结构自洽性」检查（json↔html 一致、
> 锚点可对齐、计数不混用）。它们保证「不崩」，不保证「好」—— 一份平庸但格式完整的
> PRD 能全绿通过。**测量什么就得到什么；没被测量的质量等于没有质量。**
>
> **判据上限 10 条**。超了就合并同类项 —— 判据膨胀等于没有判据。

---

## A 类 · 可脚本化（必须自动判，不许推给人）

| 编号 | 判据 | 判定线 | 怎么判 |
|---|---|---|---|
| A1 | 功能需求编号连续唯一，总数与文档自述一致 | 全通过 | 从数据源**现算**，不写死数字 |
| A2 | 需求描述使用 EARS 句式（含模态词：必须/应该/可以/禁止） | 100% | 正则扫描述列 |
| A3 | 需求描述 / 业务规则 / 验收标准**三列均非空** | 100% | 逐行查单元格 |
| A4 | 验收标准含 Given / When / Then 三段 | 100% | 逐行查 |
| A5 | 功能需求章节**无字段名 / 表名泄漏** | 0 处 | 正则扫 `snake_case` |
| A6 | 可追溯标注覆盖率（`[Dxx]`/`[Rxx]`/`[Mx]` 或显式「本文档新增」） | ≥ 90% | **现算覆盖率** |
| A7 | **口径单一定义处**：已声明口径的**定义正文**只能出现在权威处 | 0 处副本 | 声明文件 + `checks/check-duplicate-norms.py`（原 B3 升级） |

**A5 的边界**：字段名出现在第 10 章「数据与埋点需求」是**合法的**，判据只覆盖功能需求章节。
判定失败时先确认是不是合法位置，再动手改。

**A6 为什么用覆盖率而不是二元判定**：来源可以标在**模块引导语**上（7.5 的
「底线三件套：幂等(FR-29)…」）。二元判定会把这类判成假阳性，而**判据一旦假阳性，
人就会开始忽略它 —— 被无视一次的判据等于永久失效**。

### A7 的关键：指纹要取「定义正文」，不要取「口径名」（首版踩过）

首版拿口径名当指纹，实测 12 处命中里**只有 1 处是真副本**，
其余 11 处全是正当引用（「四舍六入五成双」被各文档反复提及，这很正常）。
判据立刻变成噪音。

真正区分「定义」与「提及」的是**定义正文里那句独特的话**：

```
口径名    「四舍六入五成双」                      ← 命中 12 处，其中 11 处正常
定义正文  「尾数 <5 舍；>5 入；=5 且其后全为 0…」  ← 命中 2 处，第 2 处就是副本
```

**权威处没有定论的口径，宁可不声明。** 例如「分账唯一时点 23:30」在决策层(PLAN)、
需求层(PRD)、卡片层各有表述 —— 那是不同抽象层级，不是副本。
硬指一个权威会让人去改错东西（AP-09）。**在决定权威在哪一层之前，不判。**

> A7 的声明文件是**项目内容**（写项目目录），检查器才是工作流本体。
> 因为「哪个口径、指纹是什么、权威在哪」全都要看项目。

## B 类 · 需人判（判据必须可核对）

| 编号 | 判据 | 怎么算不过 |
|---|---|---|
| B1 | **定量化**：金额 / 时限 / 比例 / 阈值必须给数值与口径 | 出现「合理时间」「适当」「尽快」等模糊表述即不过 |
| B2 | **失败路径**：支付 / 分账 / 退款 / 对账每条必须写失败时的处置 | 只写成功路径即不过 |
| B3 | **口径单一定义处**：同一口径全文只能有**一处**完整定义 | ⬆️ **已升级为 A7**（见 A 类；由 `checks/check-duplicate-norms.py` 自动判） |
| B4 | **不引入未确认结论**：新增项必须显式标注 | 出现上游未确认的业务结论且未标注即不过 |

## 元规则（管 rubric 自己）

1. **能一眼判真假的才是判据，判不了的只是口号。**
   ✗「PRD 内容要完整、逻辑清晰」　✓「涉及金额的条目必须写明舍入口径，未写明即不过」
2. **写完任何 A 类判据必须做变异测试**（`--selftest`）：好样本全绿 **且** 坏样本全红，缺一不可。
   只做好样本等于没做。
3. **假阳性必须改判据，不能靠人工忽略。** 本次 A6 从二元判定改成覆盖率制，就是因为
   模块级标注被误判。
4. **过时的判据要能失效。** 每条判据在 `review-log.jsonl` 里可追来源与命中次数；
   长期不命中或业务已变的，删掉 —— 旧判据会把新产出带偏。
