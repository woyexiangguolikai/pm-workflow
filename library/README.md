# 素材库（Component / Motion / Pattern Library）

> **这不是某个项目的产出，是一个会一直长下去的库。**
> 看到好看的动效、合适的组件、值得抄的交互，**当场存进来**；下次跑工作流时，先来这儿挑。

---

## 为什么要有它

工作流的前几层（PRD / 设计规范 / 原型）都是**为这一次交付而做**的，做完就归档了。
**只有素材库是跨项目复用、越用越值钱的。** 它是这个 skill 里唯一会随使用时间增值的部分。

所以它按「**长期资产**」设计，不按「一次性产出」设计：

| 一次性产出关心 | 素材库关心 |
|---|---|
| 这次做得对不对 | **这条素材以后还敢不敢用** |
| 符合本次需求吗 | **许可允不允许我商用** |
| 交付完就结束 | **它到底被用上过没有** |

---

## 怎么加一条（三步，别搞复杂）

1. **挑目录**：`components/`（组件）· `motions/`（动效）· `patterns/`（交互模式）。
2. **建文件**：`<前缀>-<4位序号>-<英文短名>.md`，例如 `c-0003-bottom-sheet.md`。
   序号在**同类型内**递增，不要跨类型连号（`c-0001` 和 `m-0001` 可以并存）。
3. **贴 front-matter + 正文**，然后跑一次：

```powershell
python "$env:USERPROFILE\.workbuddy\skills\pm-workflow\feedback\checks\check-library.py" `
  "$env:USERPROFILE\.workbuddy\skills\pm-workflow\library" --index
```

`--index` 会顺手把 `index.json` 重算一遍。**这个文件不要手写。**

### 条目模板

```markdown
---
id: c-0003
type: component
name: 底部抽屉（Bottom Sheet）
tags: [overlay, mobile, 选择器]
summary: 移动端从底部升起的半模态面板，用于选择器与轻量表单
license: mit
sourceUrl: https://example.com/xxx
capturedAt: 2026-10-11
support: Chrome 90+ / Safari 15+
status: active
usedBy: []
---

## 一句话
## 什么时候用
## 什么时候别用        ← 这一节最重要，不写的话三年后你会误用
## 实现要点
## 无障碍
## 依赖
## 反面参照
```

字段对照：

| 字段 | 填什么 | 为什么要 |
|---|---|---|
| `id` | `c-0003`，**短、稳定**；引用它时就用这个 | 改名会让所有引用失效 |
| `type` | `component` / `motion` / `pattern` | 决定前缀，也是检索的一级分类 |
| `tags` | 3–6 个，中文英文混着写没关系 | 检索就靠它 |
| `summary` | **一句话**，能不看正文就判断要不要 | 挑素材时你只读这一行 |
| `license` | 见下一节 | **硬门槛** |
| `sourceUrl` | 来源链接；自有原创写 `_original_` | 忘了从哪抄的素材等于不能用了 |
| `capturedAt` | `YYYY-MM-DD` | 判断「这条是不是已经过时了」 |
| `support` | **必须带版本数字** | 写「现代浏览器」等于没写 |
| `status` | `active` / `stale` / `deprecated` | `stale`/`deprecated` 必须给 `replacedBy` 或 `keepReason` |
| `usedBy` | 被哪些项目用上了 | **长期为空 = 收藏夹坟墓** |

## 🔴 许可纪律（最重要的一节）

**这是整个库里唯一会让你惹上麻烦的地方，而且它不会报错，只会在交付前夜暴露。**

| 允许 | 拦下 |
|---|---|
| `original`（自己写的）· `public-domain` · `CC0-1.0` | **`GPL` / `AGPL` / `LGPL`** —— 传染性，衍生作品也要开源 |
| `MIT` · `Apache-2.0` · `BSD-2/3-Clause` · `ISC` · `0BSD` | **`CC-BY-NC*`** —— 禁止商用 |
| `CC-BY-4.0` / `CC-BY-3.0`（需保留署名） | **`CC-BY-ND`** —— 禁止演绎（改了就是违约） |
| | **没标注许可** —— 与「不允许使用」等价处理 |

**看到素材时的动作顺序**：
1. 先找 **LICENSE / 仓库根目录 / 页面底部**，确认许可。
2. 找不到 → **不要入库**，或者入库时 `license: unknown` 并立刻被拦下（这是故意的）。
3. `CC-BY` 类必须**在正文里写清署名要求**，否则交付时会漏。

> `check-library.py` 的 **A4 会把不合规的拦下来**，并给出被拦的具体理由。
> **这条判据绝不能推给人** —— 人是记不住 200 条素材的许可的，机器记得住。

## 怎么用（工作流怎么吃这个库）

跑 **03 设计规范 / 04 原型** 之前，**先查库**：

```
1. 按 tags / type 读 index.json，挑候选        ← 只读 summary，别读全文
2. 读候选条目的「什么时候别用」一节             ← 这一步最容易被跳过，也最容易出事
3. 挑中的写进 usedBy，并记下用了它的页面/端
4. 没有合适的 → 才自己设计，设计完若能复用就回填入库
```

🔴 **两条纪律**

1. **不是「有库就必须用」**。库是**备选**不是**规定**。项目有自己的视觉方向时，
   优先级是：需求约束 > 项目设计规范 > 库。
2. **挑中就要回填 `usedBy`**。不回填的话，半年后你无法回答
   「这条素材到底有没有人用过」，也就无法清理 —— **只进不出的库会退化成负债。**

---

## 三条会要命的用法（反例）

| 反例 | 后果 |
|---|---|
| **只看截图就入库**，正文随便写 | 半年后不知道它能用在什么场景、不能用在什么场景 —— 等于没存 |
| **把没有许可的素材存进 `library/`（非 `local/`）** | 它会随 git 分发给所有人，**你替所有下游用户承担了法务风险** |
| **`usedBy` 永远为空** | 库涨到 300 条时你会开始不看它，因为它没有可信度 |

---

## 私有素材放哪

`library/local/` —— 该目录**不入 git**（见仓库根 `.gitignore`）。
放进去的素材：仅限自用、许可不清楚、或含**客户项目专有信息**的。

⚠️ 规则：**许可不合规或含客户信息的素材，只能进 `local/`，绝不进 `components|motions|patterns/`。**

## 当前状态

由 `check-library.py` 自动统计（`index.json` 是机器生成的，这里是给人看的）：

```powershell
python "$env:USERPROFILE\.workbuddy\skills\pm-workflow\feedback\checks\check-library.py" `
  "$env:USERPROFILE\.workbuddy\skills\pm-workflow\library"
```

输出会给出：条目总数、三类各几条、**已被引用几条**、许可分布、A1–A8 各项结果。

> **重点看「已被引用」这个数字。** 它长期为 0，说明这个库在坟场化 ——
> 要么是你的检索方式没进工作流，要么是入库标准太松，收了一堆用不上的。
